--- Ground truth (kubectl) ---
spark-1ba1 capacity: nvidia.com/gpu=1, allocatable: nvidia.com/gpu=1 (0 GPU-requesting
pods scheduled there -- the 'bench' pod present on that node requests no resources,
so this is a real, currently-unallocated GB10 that SkyPilot cannot see at all)
evo-x2-green / evo-x2-red: amd.com/gpu=1 each, both held by the running 'amdsvc'
sky serve service (2/2 replicas, 1x STRIXHALO each) -- so '0 of 2 free' for STRIXHALO
is correct, real utilization, not a bug.

Root cause: SUPPORTED_GPU_RESOURCE_KEYS = {'amd': 'amd.com/gpu', 'nvidia': 'nvidia.com/gpu'}
_gpu_resource_key_helper() resolves ONE resource key for the whole context by scanning
capacity keys across all nodes and returning the first match in dict order. Since the
cluster has both amd.com/gpu (evo nodes) and nvidia.com/gpu (spark) present, and 'amd'
is iterated first, get_gpu_resource_key() returns 'amd.com/gpu' cluster-wide. Every node
whose capacity dict lacks that exact key (spark-1ba1) is reported as having 0 GPUs.
